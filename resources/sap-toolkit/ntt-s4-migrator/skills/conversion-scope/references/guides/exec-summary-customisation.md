# Customise the executive summary for the customer audience

> **Why we do this:** The plugin generates a first-draft executive summary (`output/exec-summary.md`) populated with system metrics, impact classification counts, and top-risk cluster text from `ImpactMapper`. However, the draft uses generic framing. A customer's CTO needs industry-specific language, business-process context, and a clear go/no-go recommendation for their board. This guide walks the consultant through turning the machine-generated draft into a deliverable that drives decisions.

## Prerequisites

- `impact-table-walkthrough` complete: customer-reviewed impact table with top-5 risk clusters agreed
- Plugin `analyze` run complete: `output/exec-summary.md` exists (first-draft)
- Customer context from `PROJECT_PLAN.md`: go-live date, constraints, stakeholders
- RC dashboard data available: sizing tile (hardware sizing estimate) + business-functions tile

## Steps

1. **Open the first-draft exec summary**

   Open `./migration/output/exec-summary.md` in your text editor or convert to DOCX for editing.

   The draft contains these sections (generated by `DeliverableGenerator`):
   - **Migration scope** (custom object counts by type and namespace)
   - **Impact classification** (Mandatory / Advisory / Delete-candidate counts + effort totals)
   - **Top risk clusters** (from `ImpactMapper` — top-5 clusters with plain-language descriptions)
   - **Sizing estimate** (from RC dashboard sizing tile — HANA target RAM/storage)
   - **Go-live risk score** (composite from Priority-1 count + unresolved Mandatory effort)
   - **Recommended next steps** (template — must be customised)
   - **Appendix: Note summaries** (auto-linked from `NoteSummariser` output)

2. **Personalise the scope narrative**

   Replace the generic scope description with customer-specific language:
   - Mention specific custom modules or business processes ("the SD pricing custom logic in /ABC/SD*")
   - Reference the go-live date from `PROJECT_PLAN.md`
   - Frame the scope in terms of business impact, not technical counts

3. **Adjust the top-risk cluster narratives**

   The `ImpactMapper` agent produces text like "Cluster C1: 47 objects, effort L, driven by Note 3456789 (change to BAPI XYZ)." Expand this with:
   - The business process this cluster supports
   - The team/owner responsible
   - Any customer context that changes the effort estimate (e.g. "the team knows this area well — reduce to M")

4. **Validate the sizing estimate**

   The sizing tile from the RC dashboard provides a HANA sizing estimate. Cross-check with the customer's Basis team:
   - Is the sizing estimate consistent with their existing infrastructure plan?
   - Are there any planned infrastructure changes that affect the estimate?

   Note any discrepancies in the summary.

5. **Write the recommendations section**

   Replace the template "Recommended next steps" with a concrete action plan:
   - Item 1: Delete-candidates — initiate decommission process (timeline)
   - Item 2: Priority-1 Mandatory items — assign owners and sprint allocation (timeline)
   - Item 3: SAP Notes for priority items — download and review for detailed remediation steps
   - Item 4: Go/no-go criteria for migration test run

6. **Review cycle with the customer**

   Share the draft with the customer lead for a 48-hour review window. Incorporate feedback into a final version saved as `output/exec-summary-final-<date>.md` (or `.docx`).

7. **Record in PROGRESS.md**

   Append: "Exec summary finalised; version: `exec-summary-final-<date>`; customer review: complete"

## Expected behaviour

- Final exec summary in plain English, no SAP jargon unexplained
- Sizing estimate validated against Basis team input
- Recommendations section contains concrete, dated action items
- Customer has signed off (or provided written approval via email)

## Common pitfalls

| Symptom | Likely cause | Fix |
|---|---|---|
| Sizing estimate wildly different from Basis team's own calculation | RC dashboard sizing uses different baseline | Reconcile inputs; note the variance in the summary with both figures |
| Top-risk cluster text too technical for CTO audience | ImpactMapper outputs developer-level descriptions | Rewrite in business terms; have a business analyst review before sending |
| Recommendations section is still a template | Consultant forgot to fill it in | Always customise; never deliver template text |
| Customer disputes go-live risk score | Composite scoring formula not transparent | Show the formula: Priority-1 count + unresolved Mandatory effort hours; let customer adjust weighting |
